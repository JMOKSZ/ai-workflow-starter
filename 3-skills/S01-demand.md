# S01 — 需求 Skill

> **用途**: 把模糊的产品需求展开成详细的需求文档。  
> **产出**: `docs/requirements/{{功能名}}-需求文档.md`  

---

## 执行指令

### 1. 理解原始需求

先列出你理解的：
- **用户场景**：谁、在什么情况下、想达成什么
- **核心目标**：一句话说清楚做什么
- **输入/输出**：数据从哪里来、到哪里去

### 2. 展开细节

逐项分析：

| 维度 | 必须回答 |
|------|---------|
| 边界 | 这个功能做什么 & 不做什么 |
| 正常流程 | 用户一步步看到什么、系统一步步做什么 |
| 异常流程 | 网络超时、数据不存在、权限不足…每种情况怎么处理 |
| 数据影响 | 新增/修改/删除什么表？数据量级？ |
| 关联模块 | 会影响/被影响哪些已有模块？ |
| 判断条件 | 所有 if/else 分支列清楚 |

### 3. 写需求文档

在 `docs/requirements/` 下创建 `{{功能名}}-需求文档.md`，格式：

```markdown
# {{功能名}} — 需求文档

## 1. 概述
一句话说清楚做什么、为什么做。

## 2. 用户场景
- 角色：{{谁在用}}
- 触发条件：{{在什么情况下}}
- 期望结果：{{得到什么}}

## 3. 正常流程
1. 用户做X → 系统显示Y
2. 用户做Z → 系统做W
...

## 4. 异常流程
| 异常情况 | 系统行为 |
|---------|---------|
| {{网络超时}} | {{提示重试}} |
| {{数据不存在}} | {{显示404 + 日志}} |
| {{权限不足}} | {{403 + 审计日志}} |

## 5. 数据变更
- 新增表：{{表名}}，字段：{{字段列表}}
- 修改表：{{表名}}，变更：{{变更内容}}

## 6. 关联影响
- {{模块A}}：{{影响描述}}
- {{模块B}}：{{影响描述}}

## 7. 未完成 / 待确认
- {{存疑点1}}
- {{存疑点2}}
```

### 4. 输出审查清单

列出你在写文档过程中发现的 **所有不确定的问题**，用 ❓ 标记。

---

## ✅ 完成标准

- [ ] 已覆盖正常流程 + 异常流程（必须）
- [ ] 数据变更已明确
- [ ] 关联影响已列出
- [ ] 不确定问题已标注

---

## ⚠️ 注意事项

- **需要我审**：写完后告诉我「需求文档写好了」，我会看一遍再确认
- 不确定的地方用 ❓ 标记，不要替我"猜一个合理的"
- 如果原始需求本身缺失关键信息，直接列出缺失了什么，不要等我来追问
