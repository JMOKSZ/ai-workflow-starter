# S01 — 探索代码库并生成架构文档

> **用途**: 让AI第一次接触你的项目时，先理解全貌再动手。  
> **适用**: 接手老项目、新建项目、任何你想让AI理解代码库的时刻。  
> **耗时**: AI约1-3分钟，你约5分钟审阅。

---

## 执行指令

请执行以下步骤：

### 步骤1：目录漫游

先遍历项目根目录，理解整体结构：
- 看看顶层的文件和目录
- 看看 `src/` 或 `app/` 下的模块划分
- 看看 `tests/` 的覆盖方式

### 步骤2：关键文件速读

挑重要文件读：
- `package.json` / `pyproject.toml` / `Cargo.toml` → 依赖和技术栈
- 入口文件（`main.py` / `index.js` / `app.tsx` 等）
- 数据库Schema / ORM模型
- API 路由定义
- 配置文件（`docker-compose.yml`, `config.yaml` 等）

### 步骤3：写 `ARCHITECTURE.md`

在项目根目录创建 `ARCHITECTURE.md`，必须包含：

```markdown
# {{Project Name}} 架构文档

## 技术栈
- 语言/框架：...
- 数据库：...
- 基础设施：...

## 目录结构
```
<列出核心目录及作用>
```

## 核心模块
| 模块 | 职责 | 关键文件 |
|------|------|---------|
| ... | ... | ... |

## 数据流
（核心业务流程的数据流向，文字 + key-in-value 不需要图）

## 外部依赖
（第三方服务、API、SDK等）

## 关键决策记录
（Why 这么设计）
```

### 步骤4：标注不清楚的地方

在文档底部加一个 **不确定** 章节，列出你猜测但不确认的内容。

---

## ✅ 完成标准

- [ ] 已生成 `ARCHITECTURE.md`
- [ ] 已列出核心模块和职责
- [ ] 已描述关键数据流
- [ ] 已标注不确定项

---

## ⚠️ 注意

- 如果项目太大读不完，优先读主模块（80%代码在20%目录里）
- 不需要读完每一行代码，理解结构大于理解细节
- 不确定就写"不确定"，别编
