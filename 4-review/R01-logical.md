# R01 — 逻辑审（Round 1）

> **用途**: 审查代码是否符合技术文档、是否有逻辑遗漏。  
> **执行**: 由**一个Agent**执行，审查完成后交给 Round 2。

---

## 审查清单

### 1. 功能完整性
- [ ] 技术文档里列的需求，代码都覆盖了吗？
- [ ] 正常流程走得通吗？
- [ ] 异常流程有处理吗？
- [ ] 边界条件（空数据、最大值、特殊字符）有处理吗？

### 2. 一致性
- [ ] 接口签名和技术文档一致吗？
- [ ] 数据模型和技术文档一致吗？
- [ ] 返回格式统一吗？（成功/错误响应格式一致）

### 3. 副作用
- [ ] 数据库操作有事务保护吗？
- [ ] 外部调用有超时处理吗？
- [ ] 并发场景有考虑吗？
- [ ] 缓存有更新/失效吗？

### 4. 安全
- [ ] 用户输入有校验吗？
- [ ] 有SQL注入风险吗？
- [ ] 敏感信息有泄露风险吗？
- [ ] 权限检查做了吗？

---

## 输出格式

```
## 审查结果

### ✅ 通过的
- {{条目1}}
- {{条目2}}

### ❌ 需要修改的
1. **{{问题1}}**
   - 位置：{{文件:行号}}
   - 说明：{{问题描述}}
   - 建议：{{修改建议}}

2. **{{问题2}}**
   ...

### ⚠️ 建议的（非必须）
- {{可优化但非必需的建议}}
```
